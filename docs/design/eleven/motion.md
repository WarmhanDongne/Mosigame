# ELEVEN 디자인 기준 D0 · 모션 명세 (시안 A 느와르)

원본: 아티팩트 `6ea11ac6-e281-491d-9726-f891fca89aa7` 버전 `1795541629-f371` 의 `project/MotionKitNoir.dc.html`, `project/NoirProto*.dc.html`, 그리고 정적 화면(`NoirTablet*`, `NoirPhone*`, `NoirStyled*`)에 박힌 반복 애니메이션.
모든 연출은 소스에서 **CSS `@keyframes` + `animation` 만**으로 만들어져 있다(JS 타이머·`setTimeout`·Web Animations API 호출 없음, `renderVals()`는 빈 객체 또는 손패 목록만 반환). 아래 값은 브라우저 `document.getAnimations()` → `effect.getKeyframes()` 로 뽑은 값이며, 원본 키프레임 %와 그 %×길이로 환산한 ms를 같이 적었다. 1ms 단위 반올림 때문에 10099ms·3401ms 같은 값이 보이는데, 소스 % (예: 78.29%) 그대로가 근거다.

읽는 법
- 프로토타입은 “한 바퀴 반복” 데모다. 실제 앱에서는 MotionKit 규칙대로 **상태가 바뀔 때 한 번만 재생**하고, 재접속 시 애니메이션 없이 최종 상태로 그린다(MotionKit 공통 규칙 원문).
- 프로토타입 키프레임 사이 보간은 모두 `linear` 이다. 튐 곡선(`cubic-bezier(.3,1.3,.6,1)`)은 프로토타입에서는 중간 키프레임(예: `translateY(-4px)` 오버슈트, `scale(1.04)`)으로 풀어 써 있다. 곡선 원형은 MotionKit 에 있다.
- “변화 구간”은 키프레임 값이 실제로 바뀌는 시간 구간(ms)을 자동 계산한 것.
- 태블릿 측면(A측·B측) 안의 이동 값(`translateY` 등)은 **회전 전 로컬 좌표계** 기준이다(A측은 화면에서 90°, B측은 -90° 돌아가 있음). 예: 슬롯 카드 `translateY(170px)→0` 은 각 플레이어 기준 “자기 쪽 아래(화면 바깥쪽)에서 슬롯으로” 들어오는 움직임.
- 대상 표기: `영역 · <태그 .클래스> “문구”`. 휴대폰 레이어(`.lay`)는 화면 전체를 겹쳐 두고 `opacity`로 교차 전환한다.

공통 규칙(원문, 칸 10):

- 튐 곡선 cubic-bezier(.3,1.3,.6,1), 튐 폭 1.02–1.04배. 퇴장과 색 변화는 ease-out
- 기본 길이: 등장 0.3초 · 퇴장 0.2초 (토스트는 0.2 / 0.2)
- 실제 앱에서는 상태가 바뀔 때 한 번만 재생. 재접속하면 애니메이션 없이 최종 상태
- 동작 줄이기 설정이면 이동·확대·흔들림 없이 색과 투명도만
- 진동은 차례 전환 때 1회만

## 6. 소스 간 모순·애매한 점

1. 토스트 등장 방식: 정적 태블릿 화면 `tq*` = `scale(.94→1.04→1)`, 퇴장 `scale(.97)`; MotionKit 칸 1·프로토타입 = `translateY(8px)→0`, 퇴장 이동 없음.
2. 휴대폰 차례 전환: 정적 화면 `turnFlash`(빨강 번쩍) vs MotionKit/프로토타입(크림 반전). 제출 버튼 pop 1.08 vs 1.04.
3. 시간 바 색: 정적 화면·프로토타입 채움 `#e23a3a`(③은 200ms에 `#8e1a1f`로 바뀜) vs MotionKit 칸 8 기본 `#d42a2f` → 83.3%(남은 10초)부터 `#8e1a1f`.
4. 최종 동점 뽑기 카드 색: 정적 T12 는 A의 4를 흑(`slot blk`, `ptile blk`), B의 9를 백으로 그렸지만 프로토타입 ⑧은 A 4·B 9 모두 `slot wht`(백). ①/T03 의 7·3 은 둘 다 백. 뽑기 카드에 흑/백 구분이 있는지 소스끼리 일치하지 않음.
5. 뽑기 카드 위치: T12 에서 B 카드는 3×3의 3번째(오른쪽 위), A는 9번째. 프로토타입 ⑧ 에서는 B가 5번째(`kTT4`, 가운데), A가 9번째(`kTT8`)를 집는다. ① 과 T02/T03 은 A=5번째, B=9번째로 일치.
6. 토스트 유지 시간 분류: MotionKit 칸 1 설명 “행동 안내 0.6–0.7초 · 라운드 0.8–1.0초 · 공개 신호 0.5초 · 게임 승패 1.5초”. 정적 화면의 “타일 자동 제출”(T06) 0.9초는 행동 안내 범위(0.6–0.7) 밖이며 프로토타입 ③ 자막도 0.9초. 라운드 결과 “A 승리”/“동점” 0.9초, T12 “B 승리” 1.5초(게임 승패).
7. MotionKit 칸 2 설명 “제출 버튼은 흐림 → 1.04배 → 복귀 0.4초”이나 `kNPop` 키프레임은 0→660ms(22%) 동안 진행(흐림 해제 180ms, 1.04배 360ms, 복귀 660ms).
8. MotionKit 칸 2 “상태 칩이 크림색으로 0.5초 반전”: `kNChip` 은 0–501ms 크림 유지 후 501→660ms 동안 빨강으로 바뀜(ease-out). 프로토타입은 0–500ms 크림, 500→700ms 빨강으로(예: ② `kA0chip`).
9. 점수 숫자: `.score div` 는 Stardos Stencil(700만 로드) 인데 인라인 `font-weight:900` 이 붙어 있어 실제 굵기는 브라우저 합성에 달림.
10. 정적 화면 `.stage` 에 점무늬 규칙과 사선 규칙이 둘 다 있고 뒤의 사선이 이김(렌더 결과는 사선).
11. P01 과 G1 은 제목만 다르고 내용이 같은 파일이다.

## 7. 모션 기준 프레임 추출 방법

- 각 `.dc.html` 을 로컬 HTTP 서버로 열고, 아티팩트의 `artifact-type/dc-runtime.js` 를 같은 폴더의 `support.js` 로 제공해 Design Component 런타임이 실제로 렌더링하게 했다(Playwright Chromium, viewport = 원래 크기, deviceScaleFactor 1).
- 렌더 후 `document.getAnimations()` 전체를 `pause()` 하고 모든 애니메이션의 `currentTime` 을 같은 값 t(ms)로 맞춘 뒤 캡처했다. 프로토타입은 모든 레이어가 같은 길이(한 바퀴)·같은 시작이라 t 가 곧 “연출 시작 기준 시점”이다. 파일 이름 `motion-frames/<번호_이름>/<t를 5자리로 0 채움>.jpg` (예: `02_round/02600.jpg` = 2600ms). 저장소 판은 긴 변 1080px·JPEG 품질 60으로 줄였고, 원본 PNG는 git 밖 `motion-frames-full/`에 있다.
- 시점 선택: 단계 자막(`kStep*`) 시작 시점 + 모든 애니메이션의 변화 구간 시작·끝을 모은 뒤 60ms 안의 점을 합치고, 15장이 넘으면 이웃과 가장 가까운 점부터 뺐다(단계 시작은 항상 유지). 결과 시점 목록은 4절 각 연출 머리말에 있다.
- MotionKit 은 칸마다 반복 길이가 달라 `00_motionkit/` 에 동작 줄이기 정지본(`static-reduced-motion.jpg`)과 공통 시점 0·200·350·500·700·800·1000·1100·1500·2000·2500·3000ms 를 두었다(칸별 길이로 나눈 나머지 시점이 그 칸의 위치).
- 키프레임 표는 같은 페이지에서 `effect.getKeyframes()`(computedOffset × 길이)와 `getComputedTiming().duration` 으로 뽑았다. 원자료: `data/animations.json`.
- 한계: Google Fonts 차단으로 Noto Sans KR 은 로컬 Noto Sans CJK KR 로 대체, Stardos Stencil 은 없음(숫자 글꼴 다름). 브라우저 합성(그림자·`-webkit-text-stroke`·`paint-order`·`color-mix`·`filter`)은 Flutter 와 픽셀 단위로 같지 않다.
