# 흑과 백 리버스 개발·검증·배포 흐름

상태: 실행 계획 초안 · 2026-11-23. 구현·배포 완료 기록이 아니다.

## 원본과 경계

- **제품 결정의 원본:** [노션 흑과 백 리버스](https://app.notion.com/p/41809716f87e8099be9cd1197098b033) 및 그 하위 규칙·정보 공개·기기별 UX·UI 페이지. 새 제품 결정과 변경 이유는 해당 분류 페이지에 먼저 반영한다.
- **화면 참고:** [Claude 아티팩트](https://claude.ai/artifact/EfLY27nxoLMiWVnXzFWomp#page-dcb81aee8d83)의 T01–T13, P01–P11. 나머지 4개는 이전 시안. 디자인은 PRD와 코드 계약을 덮어쓰지 않는다. 작업 시 화면별 스냅샷/버전과 노션의 확인 시각을 기록한다.
- **개발 기록:** 이 저장소의 `docs/`. 계약·상태/데이터 구조는 `docs/engineering/`, 작업 계획·AI 인계는 `docs/planning/`, TEST/운영 검증과 배포 결과는 `docs/operations/`에 둔다. 대화만을 작업 인계 수단으로 사용하지 않는다.
- **기존 가이드:** `AGENTS.md`, `docs/engineering/NEW_GAME_GUIDE.md`, `docs/operations/TEST_AND_RELEASE_GUIDE.md`의 브랜치, 테스트, 승인 조건을 따른다.

최근 노션 [정보 공개 정책](https://app.notion.com/p/42009716f87e81b2854bea512ed0abab)과 [기기별 UX·UI](https://app.notion.com/p/42009716f87e81fd9f30ef302b2c5381)는 2026-11-23 변경으로 휴대폰에 **제출 접수 완료만** 표시하고 요청 중·실패 UI는 만들지 않는다고 한다. TEST Functions 전체 후보 배포는 공유 TEST 환경의 다른 검증에도 영향을 줄 수 있다. CI가 각 PR마다 자동 배포하지 않고, 하나의 통합 후보를 `TEST`에 올린 뒤 직렬화된 실행으로 배포한다. CI는 PR마다 build/lint/test와 프로젝트 ID 차단 검사까지 자동 수행한다. 운영 배포 및 공개 플래그 변경은 자동 실행 대상에서 제외하고 release manifest와 검증 결과를 먼저 보여 준다.

## 고정된 게임 검증 기준

- 타일: 각자 0–9, 11의 11개. 10 없음. 공용 뽑기 묶음은 개인 손패와 별도.
- 합 <10이면 큰 숫자, 합 ≥10이면 작은 숫자, 합 20이면 11 제출자가 승리. 같은 숫자는 항상 동점·0점·타일 소모.
- 후공은 미리 선택할 수 있으나 선공 제출 후에만 제출. 선공의 색과 후공 제출 색은 즉시 공개, 숫자·합·판정 유형은 비공개.
- 선공·후공 각 60초는 서버 시각 기준. 후공 시간은 선공 접수 직후부터 시작. 시간 초과 시 **미리 선택한 타일이 아니라** 남은 타일 중 무작위 자동 제출. 별도 뽑기에는 타이머 없음.
- 승자 다음 선공, 동점이면 선공 유지. 점수 차이 > 남은 라운드 수일 때만 조기 종료. 11라운드 누적 동점이면 직전 선공→후공 순으로 공용 뽑기, 두 수 동시 공개.
- 지난 라운드 공개 기록은 태블릿만. 휴대폰에 이전 숫자 기록 없음. 연결/복구/이탈은 기존 계약 적용, 새 정책을 임의로 추가하지 않는다.

## Claude ↔ Codex 인계 규칙

각 작업 세션 끝에 `docs/planning/BLACK_WHITE_REVERSE_HANDOFF.md`를 갱신한다. 한 번에 한 에이전트만 같은 작업 트리와 파일을 수정하고, 다음 에이전트는 HEAD·작업 트리·원격 최신 상태를 확인한 뒤 이어간다. 이전 대화의 기억보다 노션 현재 결정, 코드/설정, docs 기록과 테스트 증거를 우선한다.

인계 문서의 고정 필드:

```text
Issue / branch / HEAD / base:
노션 확인 시각 및 변경된 결정 / 디자인 화면 ID·참고 버전:
완료 범위와 변경 파일 / 아직 미완료 범위:
공개·private·server 필드 및 변경된 callable:
실행 명령 / PASS·FAIL·BLOCKED / exit code / TEST project:
배포 여부와 배포된 함수·source commit:
미확인 위험·재현 절차 / 다음 한 가지 작업:
사용자가 검증할 화면·행동 및 예상 결과:
```

새 에이전트는 인계 문서만 믿고 배포하지 않는다. 노션/코드 충돌, 새 dependency, 데이터 계약·공개 정책 변경은 근거와 영향 범위를 표시한 뒤 제품 결정을 받아 반영한다.
