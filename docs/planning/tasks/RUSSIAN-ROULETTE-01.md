# RUSSIAN-ROULETTE-01

러시안 룰렛의 서버 권위형 규칙, 휴대폰 비공개 선택, 태블릿 공개 보드,
로비 표지·색상·상세 구성품을 추가하는 작업.

## 상품·로비 정보

- 게임 ID: `russian_roulette`
- 이용 구분: 무료(`free`)
- 장르: 파티 / 심리전 / 생존
  - en: Party / Psychological / Survival
  - zh-Hans: 聚会 / 心理博弈 / 生存
  - zh-Hant: 派對 / 心理博弈 / 生存
- 2~6인, 예상 5분, 휴대폰 세로·태블릿 가로.
- 로비 팔레트: 레드 `#B3201F`, 딥 레드 `#7E1414`, 먹색 `#121110`, 크림 `#ECE3D0`.
- 표지·책등·자리 배치 테마·상세 미리보기·구성품 판을 코드로 그린다.
- 운영 카탈로그는 아직 `enabled: false`, `storeVisible: false` 후보로 유지하고 순서는 출시 때 결정한다.

## 확정 규칙

- 첫 피격 대상은 서버가 무작위로 선택한다.
- 모든 생존자는 30초 안에 `spin`, `shield`, `none` 중 하나를 비공개로 선택한다.
  모두 제출하면 바로 공개하고, 미제출자는 시간 초과 시 `none`으로 자동 선택한다.
- 총은 `spin` 수만큼 시계 방향으로 이동한다. 생존자만 세며, 탈락한 자리는 건너뜁니다.
- 멈춘 대상의 행동이 `shield`면 생존하고, `spin` 또는 `none`이면 총에 맞아 탈락한다.
- 방패는 피격 여부와 관계없이 연속 턴에 다시 고를 수 없다.
- 막았으면 같은 대상에서 다음 턴을 시작하고, 탈락하면 시계 방향 다음 생존자로 옮긴다.
- 한 턴에 한 발만 격발하므로 동시 탈락·공동 등수 규칙은 없다.
- 마지막 생존자가 승리한다. 다시하기는 자리를 유지하고 게임 상태와 첫 대상을 다시 초기화한다.
- 연결 끊김·퇴장·설정·규칙·나가기는 공용 흐름을 쓴다. 3명 미만으로 남으면 인원 부족으로 종료한다.
- 프로필은 방에 참여한 모시게임 사용자 캐릭터 ID를 쓴다.

## 구현 경계

- `packages/game_russian_roulette/`: 게임 등록, 세션, 명령, 휴대폰·태블릿 화면,
  공용 리벌버·방패·아바타 위젯, 4개 언어 룰북.
- `functions/src/russian-roulette/`: 시작, 비공개 행동 제출, 타임아웃, 연출 단계,
  격발·탈락·승리·재시작을 서버 transaction으로 처리한다.
- `game_kit` 로비 아트에 표지·책등·선반/자리 색을 등록하고 상세 미리보기와 구성품 판을 추가한다.
- 2026-11-15에 전달받은 BGM, 리볼버 회전, 총성, 방패 충돌, 우승 음원을
  진행용 태블릿에 연결했다. 회전 정지음(5번)은 자산을 받은 뒤 추가한다.

## HTML 프로토타입 연출 타이밍

- 행동 공개: 생존자 1명당 750ms + 마지막 800ms 유지.
- 총 회전: `spin` 1회당 800ms + 마지막 900ms 유지.
  총이 좌석 사이를 이동하는 실제 모션은 550ms이다.
- 격발: 격발 표시 800ms 후 피격 결과를 표시한다.
- 방패: 충돌·흔들림 500ms, 막아냄 결과는 2600ms 유지한다.
- 탈락: 탈락 결과에서 다음 턴 표시까지 3600ms를 사용한다.
- 값은 `RussianRouletteTiming`에 모아 두어 실기기 테스트 후 한 곳에서 조정한다.

### 2026-11-17 — 중단 뒤 연출 단계 정지 수정 후보

점검에서 태블릿의 연출 단계 진행이 중단 뒤 영구히 멈추는 경로를 확인했다.
`_schedule`은 예약 식별자를 `round:phase:targetUid:spinCount`로 만들고, 중단이면
식별자도 타이머도 그대로 둔 채 빠져나갔다. 그래서 중단 중에 타이머가 터져
`complete_phase`가 거절되고, 재개 시점의 식별자가 중단 직전과 같아 다시 예약되지
않았다. 서버 타임아웃은 `selecting`에만 적용되므로 빠져나올 경로가 없었다.
윷놀이 태블릿은 같은 자리에서 키를 비우고 타이머를 끈다.

식별자에 중단 여부를 포함하고, 식별자가 바뀌면 항상 타이머를 끊도록 바꿨다.
중단 중에는 예약하지 않고, 재개는 새 식별자가 되어 다시 걸린다. 중단 동안에도
단계 시계는 흘러 연출이 끝까지 그려지므로 재개 예약은 남은 시간만 기다린다.
전송이 실패하면 같은 단계에 한해 1초 간격으로 최대 3회만 다시 걸어, 일시적인
오류 한 번으로 연출이 멈추지 않게 했다. 무한 재전송은 추가하지 않았다.

판정 부분은 `roulettePhaseKey`·`roulettePhaseDelay`로 `timing.dart`에 분리해
회귀 테스트가 중단·재개를 직접 고정하도록 했다. 서버 함수·Rules·영속 데이터와
단계 시간 값은 바꾸지 않았다.

같은 파일에 있던 기존 컴파일 오류 2건(`math.max(0, n - 1)`이 `num`으로 추론)도
`math.max<int>`로 고정했다. 이 오류가 남아 있으면 패키지·통합 테스트가 로딩
단계에서 실패해 이번 수정을 검증할 수 없었다. 연출 정지와는 별개 변경이다.

남은 사항: 중단 뒤 재개에서 이미 끝난 연출을 다시 보여 줄지는 제품 결정이며
이번에는 바꾸지 않았다(남은 시간이 0이면 즉시 다음 단계로 넘어간다). 실기기
반복 중단·재개 확인은 대기다.
